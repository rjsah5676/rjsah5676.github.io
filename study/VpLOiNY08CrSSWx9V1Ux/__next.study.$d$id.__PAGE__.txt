TLS 핸드셰이크 (TLS 1.2 기준 흐름)</h2><ol><li data-list="ordered"><span class="ql-ui" contenteditable="false"></span><strong>Client Hello</strong>: 지원하는 TLS 버전, 암호 스위트 목록, 클라이언트 랜덤 값</li><li data-list="ordered"><span class="ql-ui" contenteditable="false"></span><strong>Server Hello</strong>: 선택한 암호 스위트, 서버 랜덤 값, <strong>서버 인증서</strong></li><li data-list="ordered"><span class="ql-ui" contenteditable="false"></span><strong>인증서 검증</strong>: 브라우저가 내장된 루트 CA로 인증서 체인의 서명을 확인하고, 도메인과 유효기간을 검사</li><li data-list="ordered"><span class="ql-ui" contenteditable="false"></span><strong>키 교환</strong>: (EC)DHE로 양쪽이 같은 비밀 값(pre-master secret)을 만들고, 랜덤 값들과 합쳐 <strong>세션 키(대칭키)</strong> 생성</li><li data-list="ordered"><span class="ql-ui" contenteditable="false"></span><strong>Finished</strong>: 서로 세션 키로 암호화한 메시지를 주고받아 확인</li><li data-list="ordered"><span class="ql-ui" contenteditable="false"></span>이후 HTTP 데이터는 세션 키로 암호화해서 전송</li></ol><p>TLS 1.3은 이 과정을 1-RTT(재접속 시 0-RTT)로 줄였고, 안전하지 않은 RSA 키 교환을 없앴다.</p><h2>5. 인증서와 CA</h2><table><tbody><tr><td data-row="row-1"><strong>용어</strong></td><td data-row="row-1"><strong>설명</strong></td></tr><tr><td data-row="row-2">인증서</td><td data-row="row-2">도메인, 공개키, 발급자, 유효기간 + CA의 전자서명</td></tr><tr><td data-row="row-3">CA (인증기관)</td><td data-row="row-3">인증서에 서명해 신원을 보증하는 기관 (Let's Encrypt 등)</td></tr><tr><td data-row="row-4">루트 CA</td><td data-row="row-4">브라우저·OS에 미리 내장된 최상위 CA</td></tr><tr><td data-row="row-5">인증서 체인</td><td 뜬다.</p><h2>6. 실제로 어떻게 적용되나</h2><ol><li data-list="bullet"><span class="ql-ui" contenteditable="false"></span><strong>로드밸런서에서 TLS 종료</strong>: 쿠버네티스나 클라우드 환경에서는 보통 Ingress·로드밸런서가 HTTPS를 받아 복호화하고, 내부 서버에는 HTTP로 전달한다. 그래서 서버 코드에서 요청 스킴을 보면 http로 보이고, URL을 만들 때 <code>X-Forwarded-Proto</code> 헤더를 신뢰하도록 설정해야 https 링크가 나온다.</li><li data-list="bullet"><span class="ql-ui" contenteditable="false"></span><strong>Secure 쿠키</strong>: <code>Secure</code> 속성이 붙은 쿠키는 HTTPS에서만 전송된다. 로그인 세션 쿠키에는 필수다.</li><li data-list="bullet"><span class="ql-ui" contenteditable="false"></span><strong>Mixed Content</strong>: HTTPS 페이지에서 HTTP로 이미지나 스크립트를 불러오면 브라우저가 차단하거나 경고한다.</li><li data-list="bullet"><span class="ql-ui" contenteditable="false"></span><strong>HSTS</strong>: <code>Strict-Transport-Security</code> 헤더로 "앞으로 이 도메인은 HTTPS로만 접속하라"고 브라우저에 알려, 첫 HTTP 요청을 가로채는 공격을 줄인다.</li></ol><h2>7. 면접 질문으로 정리</h2><ol><li HTTPS는 대칭키와 공개키 중 무엇을 쓰나?</strong> 둘 다 쓴다. 핸드셰이크에서 공개키 기반 키 교환으로 세션 키를 만들고, 이후 데이터는 빠른 대칭키로 암호화한다.</li><li data-list="bullet"><span class="ql-ui" contenteditable="false"></span><strong>Q. 인증서는 어떻게 검증하나?</strong> 브라우저에 내장된 루트 CA의 공개키로 인증서 체인의 전자서명을 차례로 확인하고, 도메인 일치와 유효기간, 폐기 여부를 검사한다.</li><li data-list="bullet"><span class="ql-ui" contenteditable="false"></span><strong>Q.
