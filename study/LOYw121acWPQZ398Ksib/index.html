자바스크립트 이벤트 루프: setTimeout(0)보다 Promise가 먼저 실행되는 이유

Frontend2025-10-21 22:44

자바스크립트는 싱글 스레드인데 타이머, 네트워크, 클릭 이벤트를 동시에 처리하는 것처럼 보인다. 그걸 가능하게 하는 게 이벤트 루프다. 실행 순서 퀴즈로 시작해서, 실제 코드에서 왜 중요한지까지 정리한다.

퀴즈

console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
queueMicrotask(() => console.log("4"));
console.log("5");

답은 1 5 3 4 2다.

구성 요소

  1. 콜 스택: 지금 실행 중인 함수들. 비어야 다음 작업을 꺼낸다.
  2. Web API: 타이머, fetch, DOM 이벤트는 브라우저가 처리하고, 끝나면 콜백을 큐에 넣는다.
  3. 태스크 큐 (매크로태스크): setTimeout, setInterval, 이벤트 핸들러, MessageChannel 등
  4. 마이크로태스크 큐: Promise의 then/catch/finally, await 이후 코드, queueMicrotask, MutationObserver

루프 한 바퀴

  1. 태스크 큐에서 하나를 꺼내 실행한다(처음엔 스크립트 전체가 하나의 태스크).
  2. 콜 스택이 비면 마이크로태스크 큐를 빌 때까지 전부 실행한다. 실행 중에 새로 추가된 마이크로태스크도 이번에 같이 처리한다.
  3. 렌더링할 때가 됐으면(보통 60Hz 기준 약 16ms마다) requestAnimationFrame 콜백 → 스타일 계산 → 레이아웃 → 페인트.
  4. 1로 돌아간다.

그래서 퀴즈에서 1, 5(현재 태스크) → 3, 4(마이크로태스크 전부) → 2(다음 태스크) 순서가 된다.

async/await도 결국 마이크로태스크

async function load() {
console.log("A");
await null; // 여기서 함수가 멈추고, 나머지는 마이크로태스크로
console.log("B");
}
load();
console.log("C");
// A C B

await 앞까지는 동기로 실행된다. "async 함수는 전부 비동기"라고 생각하면 순서를 잘못 예측한다.

왜 중요한가 1: 화면이 멈추는 이유

렌더링은 태스크 사이에서만 일어난다. 하나의 태스크가 500ms 걸리면 그동안 화면도, 클릭도 멈춘다. 마이크로태스크는 더 심하다. 큐가 빌 때까지 계속 실행되니, Promise 체인이 끝없이 이어지면 렌더링 기회가 아예 오지 않는다.

무거운 작업은 쪼개서 태스크 사이에 숨 쉴 틈을 준다.

async function processAll(items) {
for (let i = 0; i < items.length; i++) {
heavy(items[i]);
if (i % 200 === 0) {
// 다음 태스크로 넘겨서 그 사이에 렌더링·입력 처리가 되게
await new Promise((r) => setTimeout(r, 0));
}
}
}

await Promise.resolve()로 쪼개면 마이크로태스크라서 렌더링 틈이 생기지 않는다. 쪼갤 때는 태스크(setTimeout, MessageChannel, 지원 브라우저라면 scheduler.yield())를 쓴다. 아예 메인 스레드에서 빼야 하면 Web Worker를 쓴다.

왜 중요한가 2: 애니메이션과 측정은 rAF로

setTimeout(fn, 16)으로 애니메이션을 돌리면 화면 갱신 주기와 어긋나 끊긴다. requestAnimationFrame은 다음 페인트 직전에 실행되도록 보장되고, 탭이 백그라운드면 멈춰서 배터리도 아낀다.

반응속도 테스트처럼 "화면이 바뀐 시점"을 재야 할 때도 rAF가 기준점이 된다. 상태를 바꾼 시각이 아니라, 바뀐 화면이 그려지는 프레임의 시각을 시작점으로 잡아야 실제로 사용자가 본 시점에 가깝다.

setTimeout(fn, 0)은 0ms가 아니다

  1. 다른 태스크와 마이크로태스크가 다 끝나야 실행된다.
  2. 중첩된 타이머가 5단계를 넘으면 브라우저가 최소 4ms로 늘린다.
  3. 백그라운드 탭에서는 1초 이상으로 늘어날 수 있다.

타이머는 "최소 이 시간 뒤에"라는 뜻이지 정확한 시각이 아니다. 경과 시간을 재야 하면 콜백 안에서 performance.now()로 실제 시간을 계산한다.

Node.js는 조금 다르다

Node는 libuv 기반으로 단계(timers → poll → check …)가 나뉘고, process.nextTick 큐가 Promise 마이크로태스크보다도 먼저 처리된다. setImmediate는 check 단계에서 실행된다. 기본 원칙(현재 작업 → 마이크로태스크 → 다음 작업)은 같다.

정리

  1. 순서: 현재 태스크 → 마이크로태스크 전부 → (필요하면) 렌더링 → 다음 태스크.
  2. Promise/await는 마이크로태스크, 타이머·이벤트는 태스크.
  3. 무거운 작업은 태스크 단위로 쪼개거나 Worker로. 마이크로태스크로 쪼개면 효과가 없다.
  4. 화면과 맞춰야 하는 작업(애니메이션, 측정)은 requestAnimationFrame.
