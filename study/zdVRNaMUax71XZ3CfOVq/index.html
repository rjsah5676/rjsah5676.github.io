자바 기초 핵심 개념들 - 1단계

Java2025-5-12 15:3



특징 4가지


캡슐화

- 데이터와 기능을 하나로 묶고, 외부 접근을 제한하여 보호하는 것 (Ex. private 접근 제한자, Getter/Setter)

상속

- 부모 클래스의 기능을 자식 클래스가 물려받는 것 - 재사용성

다형성

- 같은 형태의 코드가 다양한 객체에서 다르게 동작하는 것 (Ex. 오버로딩, 오버라이딩)

추상화

- 복잡한 내부 구현을 숨기고, 사용하기 쉬운 형태로 제공 (Ex. 추상 클래스, 인터페이스)




Overriding vs Overloading





Equals와 '==' 의 차이

- '==' 은 주소(참조)값 비교 equals는 내용을 비교함

예를들어 String A= new String("abc"); String B=new String("abc");의 비교는 '=='의 경우 false equals의 경우는 true




싱글톤(Singleton)

객체를 단 하나만 생성 한 후 어디서든 동일한 객체를 참조할 수 있도록 하는 디자인 패턴.


  • 메모리 절약
  • 전역 접근
  • 상태 공유

스프링 부트에서는 @Service, @Repository, @Component, @Controller 를 통해 싱글톤 동작을 구현해 둠


단점도 있음

  • 코드 결합도 증가(강한 결합) - 유연하지 못함
  • 테스트 어려움 - mock이나 DI로 대체 힘듬
  • 의존성 감춤: 다른 객체가 싱글톤에 의존하고 있다는게 코드상 명확하지 않음



클래스 VS 객체

- 클래스는 객체를 만드는 틀

- 객체는 클래스를 기반으로 만들어진 실제 메모리에 존재하는 인스턴스




추상 클래스 VS 인터페이스

===> 추상 클래스는 공통 기능 + 확장성, 인터페이스는 기능 약속(명세서) 느낌임

-> 스프링 부트의 경우 대표적으로 JPA는 명세서, Hibernate가 그 구현체임




final의 용도

- 변수: 값을 한 번만 할당 가능 => 상수의 역할

- 메서드: 상속받은 클래스가 해당 메서드를 변경 못하도록 => 오버라이딩 금지

- 클래스: 상속 자체를 금지 => java.lang.String, java.lang.Math 등등..

===> 변경 불가능 하도록




static의 용도

클래스 단위로 공유되는 멤버를 정의할 때 사용, 객체를 생성하지 않고도 접근 가능한 정적 멤버를 만들 수 있음.

- 변수: 클래스 로드 시 메모리에 1번만 할당. => 모든 객체가 공통으로 공유

- 메서드: 객체 생성 없이 클래스명.메서드로 호출 가능, this 사용 불가




String, StringBuffer, StringBuilder 차이

String: 불변 / 수정 시 새 객체 할당

StringBuffer: 가변 / 성능은 Builder보다 낮지만, 동기화 처리가 되어있음(멀티 쓰레드 환경)

StringBuilder: 가변 / 단일 쓰레드 환경에서 가장 성능이 좋음




Checked Exception VS Unchecked Exception

- Checked Exception: 컴파일 시점에 발생하므로 반드시 처리해야 함

- UnChecked Exception: 런타임 시점에 발생하므로 후에 처리해야 함



throws VS throw

- throw: 예외를 실제로 발생 시킬 때 (예외 객체를 던짐) / Ex) throw new IllegalArgumentException("");

- throws: 예외가 발생될 수 있음을 선언부에 명시 / Ex) public void readFile(String path) throws IOException { }



컬렉션 프레임워크

- Collection

  • List (순서 O, 중복 O)
  • Set (순서 X, 중복 X)

- Map (key - value / key는 중복 X)


- 각각의 대표 용도임


- 차이점 요약



Stack VS Heap

public void test() {

int x = 5; => 스택에 저장

User user = new User(); => user는 스택, new User()는 힙에 저장

}



VO ? DAO ? DTO?


그럼 Entity는??

- DB테이블과 1:1 매핑되는 객체

Model은??

- MVC패턴에서 View로 전달할 렌더링용 데이터


DAO는 보통 JPA로 대체됨



Thread VS Runnable

Thread는 상속 방식(유연성 낮음), Runnable은 인터페이스 구현 방식(실무에서 많이 씀)



람다식?

- 간단한 함수나 익명 클래스의 구현을 더 간결하게 쓸 수 있도록 함. 주로 함수형 인터페이스랑 같이 쓰이고 생산성을 높여줌.


Runnable r = new Runnable() {

  public void run() {

    System.out.println("실행!");

  }

};

을 람다식으로 풀면

Runnable r = () -> System.out.println("실행!");


장점

  • 코드 간결성
  • 익명 클래스보다 읽기 쉬움
  • 컬렉션, 스트림과 궁합 좋음

단점

  • 디버깅 어려움 (익명 함수라 call stack 추적이 힘듦)
  • 과도한 사용 시 오히려 가독성이 떨어짐



Optional?

- 보통 리턴 값이 null일 수도 있는 메서드에 씀

- 특히 도메인 계층 -> 서비스 계층 간 전달 시 씀

Optional은 "여기 값이 있을 수도, 없을 수도 있다"는 의도를 명확히 표현하는 null-safe 도구
